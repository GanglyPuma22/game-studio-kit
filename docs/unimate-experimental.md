# Experimental UniMate reference worker

The optional [worker](../studio_tools/unimate_worker.py) implements the separate
pilot's animated-reference recipe behind the existing Kit request/result
protocol. No model, environment, download, server, catalog or GPU scheduler is
installed. Core remains stdlib and lazily loaded. Kit end-to-end inference,
original-source bake through this worker, enforced offline execution and game
adoption remain unverified. Official rest-only preprocessing does not establish
rest-only inference: **this worker refuses that unvalidated route**.

Use the existing animation, Blender bake/export and review routes. Worker
completion cannot advance an asset's imported/reviewed/accepted stage.
Keep host paths in explicit ignored host config and experiments outside Kit.

    python <KIT>/scripts/studio.py unimate inspect --project <EXPERIMENT> --config <HOST> --request request.json
    python <KIT>/scripts/studio.py unimate generate --project <EXPERIMENT> --config <HOST> --request request.json --record artifacts/unimate/<new-id>/task.json

Inspection writes nothing and imports no NumPy, Torch or Blender. Generation
launches exactly one foreground worker with an argument array, prelaunch
ownership baseline, fresh process receipt and bounded cleanup.
Do not put the pilot's independent launcher inside the worker.

## Existing envelope and reference extension

Request schema 1 retains provider unimate, experimental true, work_card, mode
text_tpos, model_profile, hashed project-relative rig_manifest, clips, limits
and execution. Host protocol_version remains 1. Existing external-worker
rest-only Mite foundation fixtures still work; they are not rest-only evidence
and cannot be submitted to the bundled reference worker.

An explicit conditioning object selects this new route:

    {
      "kind": "animated_reference",
      "object_type": "KiteEndpoint",
      "reference": {"path": "inputs/KiteEndpoint-glide-000.npz", "sha256": "<actual bytes>"},
      "captions": {"path": "inputs/captions.json", "sha256": "<actual bytes>"},
      "start_frame": 0,
      "alignment": "<actual source frame, source fps, export resampling and endpoint policy>"
    }

The reference is one real preprocessed motion NPZ, identified by its dataset
object key and filename. The rig's reference_motion_clips must be exactly
[reference]. Captions must include that filename stem. There is no random
reference selection, synthetic bootstrap, motion editing or GT clamping.
The reference supplies the stock dataset/condition factory's maps and topology;
the requested prompt replaces its caption. Hash every input before execution.

The generation object is exactly:

    {"frames":60,"sample_rate":30,"batch_size":1,"cfg_scale":3.0,"solver":"dopri5","dtype":"float32","ema":true}

One rig belongs to each request. Compare original 14 and endpoint18 through
sequential requests linked to a shared hashed comparison plan; no mixed-rig
job manager is introduced. Equal seeds with different orders/masks/counts
are not anatomically matched noise. Python, NumPy and Torch are seeded per
sample; bitwise determinism across machines/environments is not promised.

Each clip retains name, distinct sample_id (defaults to name), prompt, uint32
seed and boolean loop. Mite roles are idle/walk/graze/startle; Kite roles are
glide/powered_flap/bank_left/bank_right. The reference route requires:

    {"root_motion":"raw_preserved","desired_runtime_root_policy":"controller_owned","presentation_compensation":"full_root_view_only"}

Desired policy is in_place or controller_owned; presentation is none or
full_root_view_only. Neither changes generated bytes. Raw playback is primary.
Full compensation is a switchable labelled *viewing transform* in source world
space: source-rest Root times inverse evaluated Root, applied coherently to
the whole mesh/normals. It removes all translation AND rotation, including
banking. It is not a runtime clip. The export names the reference, space, scope,
removed components and applied_to_raw:false. Controller-owned flight/contact
integration remains a separately reviewed game change.
Never zero Root channels alone. Synthetic frame helpers are not a retargeter.

## Source and conditioning rig identities

Rig schema 1 declares subject chalk_mite or kite, profile mite31, kite14 or
kite18_endpoints, preparation animated_reference, original .blend source and
animated .glb baseline, disposable prepared_baseline .glb, condition .npy,
source_rest .npz, rig_evidence .json and reference_motion_clips.
Every artifact uses project-relative path and actual SHA-256.

source_joints records original names/parents matching the original single-skin
GLB. joints records *conditioning order*: name, parent, rest_offset (3),
rest_rotation and rest_global_rotation (normalized wxyz quaternions).
These values must match the actual condition arrays. Declare canonical_axes
Y_up_Z_forward and a proper uniform canonical_from_source 4x4.

Mite keeps all 31 original bones. Kite14 keeps the original 14. Kite18 adds
only LWingOuterEndpoint, RWingOuterEndpoint, LHindGripEndpoint and
RHindGripEndpoint, each parented to its unsuffixed original bone.
helpers records name/parent and weighted:false, use_deform:false, animated:false;
original parent relations remain identical. Prepared GLB retains every helper.
The source_rest NPZ contains original names, integer parents (-1 root),
rest_world_bones and C; C describes this condition's canonical transform.
For endpoint preparation, project captured source-rest onto original 14 and
retain endpoint C. Do not substitute the other rig's normalization transform.

rig_evidence binds baseline_sha256 and prepared_baseline_sha256 and declares
source_names_parents_rest_preserved:true, mesh_skin_preserved:true.
Core checks the record and GLB names/hierarchy; it does not authenticate Blender
rest or mesh/weights. Worker checks actual NumPy rest/topology/finite values. Captured float32 source-rest matrices use a 1e-5 orthogonality tolerance without changing their values; canonical transforms and trajectory math keep stricter validation.
Existing Blender baking must independently verify source rest/skin/geometry.
Retain both identities; do not silently replace production source with helpers.

Capabilities partition conditioning names into independent_rotation_joints
and unsupported_rotation_joints, with unsupported_joint_policy source_rest_only.
All stock-decoder leaves are unsupported: Mite mandibles and all 14 lower legs.
Endpoint helpers restore representable parent channels, not every skeletal DOF;
Head and other remaining leaves still lose independent rotations.
conditioning_modes is exactly [animated_reference]. translation_policy is
fixed_rest_offsets; unsupported_translation_joints lists all nonroot condition
joints. Never borrow authored channels without labelled hybrid provenance/review.
Slug contact shape-key authoring stays outside this skeletal route.

## Ownership, cancellation and receipts

Retain batch 1, one attempt, <=8 samples, <=3600 seconds, bounded again by UTC cutoff.
GPU needs an externally owned hashed reservation valid through cutoff. This is
coordinator evidence, not arbitration or a quiet-host guarantee. Coordinate actual
GPU validation with the parent while other tasks are active. Physical cuda:3 stays
in request/reservation; masking exposes worker-local cuda:0. CPU visibility is empty.

The same remaining budget covers all phases/samples. GPU probes select the
physical ordinal, requiring >=3072MiB free VRAM, <65% utilization and >=2048MiB
free RAM. Contention refuses and retains partial evidence; it never interrupts
competitors or waits/retries with a resident model. The outer owned runner is
the hard timeout/interrupt boundary during long library calls.
Optional cancel.json beside input/result carries exact request_digest;
cooperative checkpoints observe it. No status/cancel server or PID-based
signalling is added. Never reuse a run or kill from an old receipt.

Input retains the envelope plus runtime, worker_profile and host_entries mapping
python/worker IDs in assets. Result retains digest/clip/artifact checks and binds
conditioning_digest, generation_digest, runtime_digest. It reports raw_motion
preserved, array_validation worker_checked, actual frame count and loop_validation
unverified.60 frames at 30 Hz span 0..1.966667 s, not a proven seamless two-second loop.
evidence.json retains condition tensor hashes/shapes/dtypes, actual dependency
versions, sampling-phase timing and allocator peaks. These are not game or
cleanroom performance benchmarks. Structured bound failures remain failures;
cleanup evidence takes priority.

## Viewer boundary and current evidence

motion-export.json is a portable project-relative artifact/provenance inventory,
format studio-unimate-motion-export schema 1. It binds request, source/condition
rig and helper mapping, capabilities, conditioning, generation, clips and evidence.
It defaults raw_playback_primary:true, states the full-root presentation contract
and keeps production_acceptance:pending. It contains no host roots/credentials.
The viewer consumes/copies hashed artifacts through its existing catalog; Kit
creates no second catalog/server. The optional source bake below emits a
separate derivative receipt binding this export's hash to raw GLB/source/fresh-
import evidence. Never edit the original export or attach runtime acceptance
merely because a file plays.

## Optional source bake through the existing runner

The packaged `studio_tools/blender_scripts/unimate_bake.py` and
`unimate_verify.py` are invoked by a project-owned wrapper through
`studio blender run`; no bake CLI branch, launcher or catalog is added. The
wrapper imports the explicitly resolved Kit package and runs the packaged
module. Declare the isolated output `.blend`, GLB, expectations and JSON receipts
as runner results. A recipe binds the completed worker record/export by SHA-256,
sample ID, an actual full-DOF authored control capture, both implementation
hashes, a new output directory and unique generated clip name. It carries
`schema_version:1`, `kind:unimate_source_bake`; runtime acceptance stays pending.
Inputs/outputs belong outside Kit; never overwrite the original source or worker
export. The control capture is separate evidence, never a generated channel source.

This bounded profile requires one weighted mesh/primitive, one original armature,
unit source basis, at most four positive influences, no constraints/drivers,
no shape keys or extra modifiers, and full bone inheritance with local location.
Other profiles refuse rather than silently change authoring or export policy.
Slug shape-key/contact work remains in its authored Blender route.

Recover every decoded joint first. Identity-delta rest uses canonical T-pose
joint positions and identity rotations; stored T-pose bone quaternions are basis
provenance, not an extra decoder rotation. Invert `C=[sR,t]` once for positions
and orientations, calibrate each original bone with
`H_j=inverse(Phi(D0_j))*B0_j`, then apply `Phi(D_j(t))*H_j`. Only after full
recovery/conversion retain originals by NAME. Captured rest order may differ
from decoded projection order. Float32 source bases are retained unchanged at
their declared1e-5 capture tolerance; canonical/trajectory checks stay strict.
Blender `Bone.convert_local_to_pose(...,invert=True)` solves the actual rest and
parent bases. Preserve raw Root translation/rotation; auxiliary facing is not
composed twice. No authored leaf animation or controller transform is injected.

Create a distinct action with the original rotation modes, authored actions/NLA,
scene timing, geometry, materials, hierarchy, rest and weight fingerprints intact.
Generated key times express30Hz in the source's original frame rate. Export-only
action copies move clip origins to zero and sample at30Hz, preserving seconds;
the saved source retains its original authored curves and frame rate. Fresh-process
verification checks that saved source, unchanged baseline GLB geometry/skin/rest/
materials and authored clips, then imported skin motion and mesh deformation
against independent decoded/source-space expectations. Runtime LBS uses the
actual preserved baseline GLB buffers: existing exporter pruning of tiny source
influences must be disclosed separately, not mistaken for a source edit or hidden
by relaxed weight matching. Keep every original weight in the editable `.blend`.

Publish only a successful, independently reviewed GLB derivative through the
existing fieldbook CLI/API, using the real embedded clip order. Retain exact
worker/source/bake/verification receipts in provenance. Preserve selected takes,
comments and game pins; new candidates remain unselected with readiness unset.
Successful bake/import is technical evidence, not quality, seamless looping,
native offline containment or pinned Godot/controller qualification.

The reviewed optional worker completed one bounded Kite18 animated-reference run
on the existing host: 76.688 seconds owned-process wall time, with 43.242 seconds
sampling. Its 441.208MiB allocated / 516MiB reserved peaks are sampling-phase
PyTorch allocator values only; they exclude other applications and CPU/text work.
This is one host/profile result, not a clean benchmark or universal 8GB claim.
The source-bake proposal has separate reconstruction/import receipts and remains
subject to independent review before fieldbook registration. Native network
containment, rest-only inference and pinned Godot/controller qualification remain
unproven. Historical pilot results below are separate from this Kit worker run.

7.304->0.490mm (93.3%) with unchanged geometry/weights. This is representation
fidelity, separate from generated quality. Full-root compensation can hide banking.
Human/gameplay-distance, controller/contact and pinned double-precision Godot checks
remain pending; authored production clips retain authority. Earlier Mite and
Kite pilot receipts do not prove this worker's execution, ownership, offline
operation or bake. User selection alone is not production acceptance.
