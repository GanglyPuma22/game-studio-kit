# Studio Tripo

Inputs: declared project/output root, approved asset brief and exact reference,
source asset when present, requested operation, owner and numerical time,
credit, submission and geometry budgets. Read [provider workflow](references/provider-workflow.md)
before any provider operation. Resolve the kit from this file's location;
generated assets and private receipts belong outside the kit.

There is no `studio tripo` command yet. This skill adds a workflow, not a
provider adapter, host credential mapping, doctor capability or tested live
integration. Use a verified official SDK/CLI or the available Tripo Studio UI;
never invent helper commands, provider profiles, flags or compatibility.

Choose the smallest operation that answers the work card's question:

| Need | Route |
|---|---|
| New specimen from an approved prompt/reference | One generation, scoped to the actual game asset |
| Existing specimen with a structural obstacle | One supported preprocessing step; include required upload/import prerequisites in its total budget |
| Trivial cuts, material repair, scale or camera changes | Local [Blender](../studio-blender/SKILL.md) first |
| User selects another provider or Tripo cannot meet the contract | Optional [Meshy](../studio-meshy/SKILL.md), subject to its own authorization and balance |

Do not default to heads/busts, segmentation or a chain of paid repairs. Existing
assets stay authoritative until comparison shows that a candidate resolves the
declared obstacle without losing the required identity. Provider choice follows
user preference and verified capability; neither provider has a general quality
priority.

1. Verify the selected product surface, current operation/model compatibility,
   official client version and exact accepted parameters. Record primary-source
   links and the check date. Check current balance and full operation cost before
   spending; API wallet and Studio credits are separate pools. Verify the selected
   plan's model-specific export allowance, output-use rights and public/private
   visibility before uploading or submitting; a generation balance alone does
   not establish a usable export or production entitlement. Existing explicit
   authorization stands when it covers this operation and total cost.
2. Reserve one unique private receipt and output directory. Preserve source and
   reference hashes. Record authorized numerical bounds before submission,
   including any required import/upload charges and possible export charges.
   Unknown cost, insufficient balance or an ambiguous previous submission stops
   further paid work.
3. Submit once, persist its task ID immediately, and use one supported bounded
   blocking SDK/CLI wait or event-driven Studio completion. Do not poll from the
   agent, hand-write a watch loop or duplicate a still-running submission. The
   host call must cover the declared timeout; if it yields early, use the host's
   single completion retrieval. A timeout is an unresolved task, not permission
   to regenerate.
4. Download into project-owned source storage promptly, preserve the original,
   validate actual file signatures and hashes, and record terminal status and
   actual charge/refund when available. Sanitize shared receipts; keys, upload
   credentials and signed download URLs remain private.
5. The foreground owner inspects the exact archived result in native Blender
   against the original and fixed reference at close and player scale. Measure
   triangles, topology, dimensions, UVs/materials and useful part boundaries
   against the numerical asset budget before rigging or replication. Route a
   usable specimen to [Godot](../studio-godot/SKILL.md) and
   [review](../studio-review/SKILL.md) as the work card requires. Workers return
   bounded evidence; provider success and tests do not establish acceptance.

Return the sanitized receipt, source/output hashes and paths, measured budget
results, cost evidence and next review question. Preserve failed candidates and
unresolved task IDs. A further generation, repair, rig or export is a separate
decision within the remaining authorization; it never follows automatically.
