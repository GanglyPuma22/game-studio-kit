# Fish REST file speech

Original kit adapter; narrow independently implemented profile. Official contract checked 2026-09-05: [TTS endpoint](https://docs.fish.audio/api-reference/endpoint/openapi-v1/text-to-speech), [OpenAPI](https://docs.fish.audio/api-reference/openapi.json). No live/account readiness is claimed.

`audio speech --provider fish --project <GAME> --request <REQUEST.json> --budget <BUDGET.json> --provenance <RIGHTS.json> --record artifacts/fish-intent.json --output source/voice.mp3` uses configured `FISH_AUDIO_API_KEY`. Keep actual voice configuration outside public examples. Request fields are `text`, explicit `model_id` and a single authorized `reference_id` string. Supported model headers: `s1`, `s2-pro`, `s2.1-pro`, `s2.1-pro-free`. Missing/unknown headers may fall back to paid `s2.1-pro` at the service, so this adapter rejects them locally. Zero budget forbids all submissions, including free-named models.

POST `/v1/tts` uses bearer authentication, a `model` header and JSON containing text/reference_id plus fixed `format: mp3`, `sample_rate: 44100`, `mp3_bitrate: 128`. There is no `streaming:false` field. REST may return chunked raw binary; the transport buffers the complete response to an archived original. MP3 signature and bounded response checks do not establish listening quality. MIME is retained when supplied, not required to equal an undocumented value.

The common durable intent is created before submission. Uncertain response, validation, output or final metadata failures remain `SUBMISSION_UNKNOWN`; reconcile provider history without resubmitting or switching providers. `ARCHIVED` only means the original and metadata were saved. Preparation, cue wiring and actual listening remain separate.
